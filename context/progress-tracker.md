## Architecture Decisions

- WHO fact sheets chosen as the sole approved source for the MVP (not NCDC or Lagos State Ministry of Health) — driven by ingestion feasibility at hackathon speed. See `architecture.md`.
- Nigerian Pidgin chosen as the single second-language mode — satisfies both the "multiple languages" and "simplified communication" brief bullets with one feature.
- No end-user auth, by design — matches the brief's privacy emphasis and the do-not-build list.
- **AI provider corrected: OpenAI, not Anthropic Claude** (this entry previously said Anthropic — inaccurate as of the provider swap below; corrected in place rather than left stale, since a future reader would otherwise trust the wrong provider).
- **AI provider switch: Anthropic Claude → OpenAI, for generation/classification (embeddings were already OpenAI since Spec 03).** Reason: no Anthropic API key available (the $20 Anthropic Console credit line in this entry's prior version was never actually usable — Spec 05's live generation path stayed unverified through Spec 05's implementation for exactly this reason). Consolidates the app to one provider instead of two. `lib/ai/client.ts` is the only file that changed — confirmed by design (`architecture.md`'s stack section names this file as the sole swap point) and by a clean `tsc`/`lint` pass touching only that file plus `prompts.ts` (see the boundary-violation note below).
  - **Model: `gpt-5.6-terra`.** OpenAI's own launch positioning for Terra is "high-volume business tasks like customer support, internal tools and document analysis" — a direct match for document-grounded health Q&A — and "competitive performance to GPT-5.5 while being 2x cheaper." Ruled out `gpt-5.6-luna` (cheapest tier, positioned for lower-stakes drafting/summarization — this product's hard invariants around citation faithfulness and never fabricating grounded claims argue for more capability than the bargain tier) and `gpt-5.6-sol` (flagship "hardest problems" tier — coding/security-research grade, unnecessary cost for straightforward RAG QA).
  - **Cost comparison to the original Sonnet 5 plan:** Terra is $2.00/1M input, $12.00/1M output — Sonnet 5 was $2.00/1M input, $10.00/1M output. Close to cost-neutral (Terra's output tokens run ~20% more), not a downgrade in spend to get around not having an Anthropic key.
  - **Latency:** not independently benchmarked at this project's scale (a live single-request curl test succeeded well within the demo's ~5s target — see Spec 05's verify checklist — but that's one data point, not a load test). No latency red flags expected: Terra is explicitly the "balanced" mid-tier, not the slower flagship reasoning tier, and `reasoning_effort: "low"` is set in `lib/ai/client.ts` since this is straightforward RAG QA, not a hard reasoning task.
  - **Structured output mechanism:** `openai.chat.completions.parse()` + `zodResponseFormat()` (confirmed present in the installed `openai@7.5.0`) satisfies code-standards.md's "structured JSON validated against the shared zod schema" requirement exactly as the original Anthropic `messages.parse()` design did — same contract, different SDK call. Confirmed by reading the installed SDK's source directly (not assumed): `chat.completions.parse()` throws a raw `ZodError`/`SyntaxError` on schema-mismatch/invalid-JSON (not wrapped in an `OpenAIError` subclass, unlike Anthropic's `AnthropicError` wrapping) and separately throws `LengthFinishReasonError`/`ContentFilterFinishReasonError` for truncated/filtered output (these do extend `OpenAIError`) — given that mixed taxonomy, `lib/ai/client.ts` catches broadly (any thrown error ⇒ treat as malformed, retry) rather than narrowing to one error class, which would have missed the schema-mismatch case.
  - **Boundary violation found and fixed, not left in place:** `lib/ai/prompts.ts`'s `buildMessages()` previously returned `Anthropic.MessageParam[]` directly — importing the Anthropic SDK's own type into a file that `code-standards.md`'s file-organisation rule and `architecture.md`'s "swap `lib/ai/client.ts` only" both imply should be provider-agnostic. This predates the swap (Spec 05 never exercised a second provider, so it went unnoticed) — it wasn't quietly patched, it's called out here per instruction. Fixed by having `buildMessages()` return a plain `{ role, content }[]` shape instead.
  - **Citation-metadata trust bug found and fixed during live verification, also predates the swap:** the model was asked to fill in each citation's `source_title`/`source_name`/`source_url` itself, but `lib/ai/prompts.ts` never actually gave it the source URL — so it had to guess. Live-tested with a real malaria query: the model correctly cited a real `chunk_id` (that part *was* validated against the retrieved set, per Spec 05's design) but returned `source_url: null` for a source that has a real WHO URL in the live DB. Unlike `chunk_id`, none of that metadata was ever cross-checked — a gap in the same `architecture.md` invariant 5 ("every citation validated against an actual retrieved chunk ID... never trusted unchecked") that Spec 05 otherwise enforces carefully. Fixed by splitting the schema: the model now only reports `cited_chunk_ids` (which chunks it used); `lib/ai/client.ts` reconstructs the full citation objects (`source_title`/`source_name`/`source_url`) from the already-trustworthy `RetrievedChunk` data server-side, never from the model's own output. Re-verified live after the fix — `source_url` now correctly populated.
  - New env var: none — `OPENAI_API_KEY` already existed (Spec 03). `ANTHROPIC_API_KEY` removed from `.env.example` and `.env.local`.
  - `@anthropic-ai/sdk` uninstalled from `package.json` — confirmed via a repo-wide search that no source file imports it any longer before removing it, not just deleted on assumption.
- Tailwind CSS v4 confirmed (already scaffolded in the initial commit, along with Next.js 16.3.2 and shadcn/ui — ahead of Spec 01 being formally written). Tailwind v4 is CSS-first config with no `tailwind.config.ts`; theme values live in an `@theme` block in `app/globals.css`. `ui-context.md` and `code-standards.md` originally said "tailwind.config.ts" (a v3 assumption) — corrected both to point at `app/globals.css`'s `@theme` block instead. User confirmed this direction over creating a `tailwind.config.ts` + `@config` shim.
- `ui-context.md`'s teal interactive-color token renamed from `accent` to `brand` — shadcn/ui already reserves `--accent` internally as a neutral hover-background token used by every generated primitive; reusing the name would cause one value to silently clobber the other in the CSS `@theme` block. User confirmed renaming the brand token rather than overriding shadcn's `--accent`. Use `bg-brand` / `text-brand` / `border-brand` in components going forward, not `accent`.
- HNSW chosen over ivfflat for `kb_chunks.embedding`'s similarity index (`database-schema.md` left this open — "ivfflat (or hnsw)"). This MVP's corpus is 12 WHO fact sheets, likely well under a thousand chunks; ivfflat's `lists` parameter is tuned against row count and needs data present (plus `ANALYZE`) to build a good index, which has no real signal at this scale. HNSW needs no such tuning and gives accurate search from the first row. Uses `vector_cosine_ops` to match the `<=>` operator in `match_kb_chunks`.
- **Embedding provider/model chosen: OpenAI `text-embedding-3-small`** (resolving the "Open decision" in `architecture.md`'s stack table). Outputs 1536 dimensions natively, an exact match to `kb_chunks.embedding vector(1536)` (already applied in Spec 02's migration) with no config or schema change needed. User confirmed over Voyage AI (Anthropic's own recommended embedding partner), which was ruled out only because no Voyage model natively outputs 1536 dims (options are 256/512/1024/2048) and would have required either a new migration to widen/narrow the column or a workaround — Anthropic is still used for all generation/classification; only embeddings come from OpenAI. New env var: `OPENAI_API_KEY` (added to `.env.example`).
- **Chunking strategy chosen: fixed-size token window with overlap** — ~400 tokens per chunk, ~50 token overlap between consecutive chunks within a source, using `cl100k_base` tokenization (the encoding OpenAI's `text-embedding-3-small` uses) via the `gpt-tokenizer` package so "tokens" means the same thing the embedding model sees. Chosen over paragraph/section-based chunking because WHO fact-sheet HTML formatting isn't consistent enough across pages to rely on paragraph boundaries alone; a fixed window is robust to that variance. `chunk_index` increments per chunk within a source, starting at 0.
- **Red-flag rules: both drafted judgment calls accepted as-is** (`data/red_flag_rules.json`, reviewed by the project owner, no edits made). (1) Severe pregnancy danger signs (heavy bleeding, seizures, severe headache + vision changes, postpartum fever, reduced fetal movement) → `category: 'emergency'`, not `maternal-care` — these are "go now" signs and `maternal-care`'s one directory entry is the antenatal clinic, a continuity-of-care destination, not an emergency one. (2) Imminent self-harm risk (stated plan/means, already self-harmed, command hallucinations to self-harm) → `category: 'mental-health'`, not `emergency` — kept under the taxonomy's own category despite the one `mental-health` directory entry (Federal Neuro-Psychiatric Hospital, Yaba) having an unverified contact number. This second call is explicitly **not** fully closed: see Open Questions above — Spec 06 may still need distinct escalation copy/handling for this category, separate from the row's stored `category` value.
- **Spec 06 implementation decisions, all matching the written spec — logged here per the sync table rather than left only in the spec file:**
  - `EscalationResponseSchema` and the zero-retrieval/no-grounded-info `ChatResponseSchema` payload are both run through `.parse()` before being returned from `app/api/chat/route.ts`, even though neither is model output — cheap extra insurance that the hand-constructed object actually matches the documented response contract, catching a shape bug at the route layer instead of letting a malformed response reach the client. Not explicitly required by Spec 06's text, but consistent with code-standards.md's structured-output-validation spirit and adds no real cost.
  - The escalation branch's category/severity resolution (Decision 6) includes an explicit, documented "should be unreachable" guard: if neither the deterministic match nor the AI classifier actually yields a resolvable category+severity inside the branch that only runs when at least one of them fired, the route logs and returns the generic 500 rather than assuming the combination logic can never fail. This mirrors Decision 9's own reasoning (`matched_entries` handling a zero-row case that "shouldn't happen" but is still coded for) applied to one more spot.
  - Verified the classifier-failure degrade path (Decision 8) by overriding `OPENAI_API_KEY` via shell env on a restarted dev server rather than `.env.local` — Next.js's env precedence puts `process.env` above `.env.local`, so this exercised a genuine 401/retry/degrade cycle without touching the real secrets file.
- Direct Postgres connections to Supabase (`db.<ref>.supabase.co`) are IPv6-only (no `A` record) and unreachable from this build sandbox's network. Migrations must run through the **Session mode connection pooler** (`aws-*.pooler.supabase.com`, port 5432) instead — this is Supabase's own documented fix for IPv4-only environments, not a workaround. In practice the migration also succeeded through the Transaction-mode pooler (port 6543) for this single-shot multi-statement DDL run, but Session mode is still the one to reach for by default — Transaction mode's per-statement connection multiplexing is not guaranteed to hold up for more complex future migrations.
