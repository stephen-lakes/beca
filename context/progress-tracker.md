- **AI provider switch: Anthropic Claude → OpenAI, for generation/classification (embeddings were already OpenAI since Spec 03).** Reason: no Anthropic API key available (the $20 Anthropic Console credit line in this entry's prior version was never actually usable — Spec 05's live generation path stayed unverified through Spec 05's implementation for exactly this reason). Consolidates the app to one provider instead of two. `lib/ai/client.ts` is the only file that changed — confirmed by design (`architecture.md`'s stack section names this file as the sole swap point) and by a clean `tsc`/`lint` pass touching only that file plus `prompts.ts` (see the boundary-violation note below).
  - **Model: `gpt-5.6-terra`.** OpenAI's own launch positioning for Terra is "high-volume business tasks like customer support, internal tools and document analysis" — a direct match for document-grounded health Q&A — and "competitive performance to GPT-5.5 while being 2x cheaper." Ruled out `gpt-5.6-luna` (cheapest tier, positioned for lower-stakes drafting/summarization — this product's hard invariants around citation faithfulness and never fabricating grounded claims argue for more capability than the bargain tier) and `gpt-5.6-sol` (flagship "hardest problems" tier — coding/security-research grade, unnecessary cost for straightforward RAG QA).
  - **Cost comparison to the original Sonnet 5 plan:** Terra is $2.00/1M input, $12.00/1M output — Sonnet 5 was $2.00/1M input, $10.00/1M output. Close to cost-neutral (Terra's output tokens run ~20% more), not a downgrade in spend to get around not having an Anthropic key.
  - **Latency:** not independently benchmarked at this project's scale (a live single-request curl test succeeded well within the demo's ~5s target — see Spec 05's verify checklist — but that's one data point, not a load test). No latency red flags expected: Terra is explicitly the "balanced" mid-tier, not the slower flagship reasoning tier, and `reasoning_effort: "low"` is set in `lib/ai/client.ts` since this is straightforward RAG QA, not a hard reasoning task.
  - **Structured output mechanism:** `openai.chat.completions.parse()` + `zodResponseFormat()` (confirmed present in the installed `openai@7.5.0`) satisfies code-standards.md's "structured JSON validated against the shared zod schema" requirement exactly as the original Anthropic `messages.parse()` design did — same contract, different SDK call. Confirmed by reading the installed SDK's source directly (not assumed): `chat.completions.parse()` throws a raw `ZodError`/`SyntaxError` on schema-mismatch/invalid-JSON (not wrapped in an `OpenAIError` subclass, unlike Anthropic's `AnthropicError` wrapping) and separately throws `LengthFinishReasonError`/`ContentFilterFinishReasonError` for truncated/filtered output (these do extend `OpenAIError`) — given that mixed taxonomy, `lib/ai/client.ts` catches broadly (any thrown error ⇒ treat as malformed, retry) rather than narrowing to one error class, which would have missed the schema-mismatch case.
  - **Boundary violation found and fixed, not left in place:** `lib/ai/prompts.ts`'s `buildMessages()` previously returned `Anthropic.MessageParam[]` directly — importing the Anthropic SDK's own type into a file that `code-standards.md`'s file-organisation rule and `architecture.md`'s "swap `lib/ai/client.ts` only" both imply should be provider-agnostic. This predates the swap (Spec 05 never exercised a second provider, so it went unnoticed) — it wasn't quietly patched, it's called out here per instruction. Fixed by having `buildMessages()` return a plain `{ role, content }[]` shape instead.

Fixed by splitting the schema: the model now only reports `cited_chunk_ids` (which chunks it used); `lib/ai/client.ts` reconstructs the full citation objects (`source_title`/`source_name`/`source_url`) from the already-trustworthy `RetrievedChunk` data server-side, never from the model's own output. - **Embedding provider/model chosen: OpenAI `text-embedding-3-small`** (resolving the "Open decision" in `architecture.md`'s stack table). User confirmed over Voyage AI (Anthropic's own recommended embedding partner), which was ruled out only because no Voyage model natively outputs 1536 dims (options are 256/512/1024/2048) and would have required either a new migration to widen/narrow the column or a workaround — Anthropic is still used for all generation/classification; only embeddings come from OpenAI. New env var: `OPENAI_API_KEY` (added to `.env.example`).
- **Chunking strategy chosen: fixed-size token window with overlap** — ~400 tokens per chunk, ~50 token overlap between consecutive chunks within a source, using `cl100k_base` tokenization (the encoding OpenAI's `text-embedding-3-small` uses) via the `gpt-tokenizer` package so "tokens" means the same thing the embedding model sees. Chosen over paragraph/section-based chunking because WHO fact-sheet HTML formatting isn't consistent enough across pages to rely on paragraph boundaries alone; a fixed window is robust to that variance. `chunk_index` increments per chunk within a source, starting at 0.
